# 隐私与 GDPR 合规说明

本文档说明 Skyfire 处理哪些个人数据、出于什么目的、保留多久、有哪些安全
措施，以及如何支持数据主体权利。Skyfire 是**自托管**软件：部署者是数据控制者
（controller），项目本身不接收、不回传任何数据。

> 本说明基于软件的实际行为，不构成法律意见。请结合你的司法辖区与部署环境
> 由 DPO/法务确认。

---

## 1. 角色与数据流向

- **控制者**：运行 `skyfired` 的组织/个人。
- **处理者**：无。软件不向任何第三方发送数据；更新检查（`skyfire update`）
  仅在管理员**手动**执行时访问 GitHub Releases，不涉及个人数据。
- **数据流向**：全部本地。隧道流量（WireGuard）端到端加密，服务器只做转发与
  必要的地址/路由/NAT 处理。

---

## 2. 处理的数据、目的与合法性基础

| 数据 | 位置 | 目的 | 合法性基础（示例） |
| --- | --- | --- | --- |
| 管理员用户名、密码、TOTP 密钥 | 进程内存 / `totp.json` | 控制台登录与访问控制 | 合法利益 / 合同履行（GDPR Art. 6(1)(b)/(f)） |
| Peer 名称、备注 | `config.json` | 便于运维识别设备 | 合法利益 |
| 隧道地址、公钥、预共享密钥、客户端令牌 | `config.json` | 建立与续期隧道 | 合同履行 |
| Peer 端点、AllowedIPs、保活 | `config.json` | 连接配置 | 合同履行 |
| 连接状态、最近握手、收发字节 | 内存（运行时） | 运行监控 | 合法利益 |
| HTTP 访问日志（方法、路径、状态、字节数、耗时） | 服务日志（stderr/journald） | 安全审计与故障排查 | 合法利益 |
| 客户端 IP（HTTP 对端地址） | 仅内存、仅用于登录暴力破解防护，短时过期 | 安全（Art. 32） | 合法利益 |

**最小化**：不采集姓名、邮箱、地理位置、设备指纹或行为画像；不做统计上报。

---

## 3. 隐私设计（Privacy by Design / Default，Art. 25）

- **默认不改变系统**：`-dry-run` 可预览所有操作。
- **默认开启两步验证（TOTP）**：首次登录强制绑定身份验证器；可用
  `-totp=false` 显式关闭。
- **默认最小权限**：配置文件与 TOTP 文件权限 `0600`；配置目录 `0750`。
- **凭证不落盘（除 TOTP 密钥外）**：Web 密码只存在进程内存，不写入配置文件。
- **日志脱敏**：`/api/p/<token>/...` 的令牌在访问日志中替换为 `<redacted>`。
- **会话最小化**：Session 仅存于内存、24 小时过期，Cookie 带 `HttpOnly` +
  `SameSite=Lax`，HTTPS 下自动加 `Secure`。

---

## 4. 存储位置与保留期限（Art. 5(1)(e)）

| 数据 | 位置 | 保留 |
| --- | --- | --- |
| `config.json`（接口/Peer/密钥/令牌） | `-config` 指定路径（默认 `/etc/skyfire/config.json`） | 直到管理员删除对应接口/Peer 或整库 |
| `totp.json`（TOTP 密钥与绑定状态） | 与 `config.json` 同目录 | 直到 `skyfired totp reset` 或删除文件 |
| Session | 进程内存 | 24 小时（可主动登出立即失效） |
| 登录失败计数（含客户端 IP） | 进程内存 | 15 分钟滚动窗口，重启即清空 |
| HTTP 访问日志 | 由部署的日志系统决定 | **由控制者设定**；建议配合 `logrotate`/journald 设置上限 |

> 建议：为服务日志配置轮转与保留上限（例如 journald `MaxRetentionSec=`），
> 并在隐私声明中写明日志保留期。

---

## 5. 安全措施（Art. 32）

- **传输**：隧道流量使用 WireGuard 加密；控制台建议置于 HTTPS 反向代理之后。
- **认证**：
  - 单用户密码 + **TOTP 两步验证**（RFC 6238，HMAC-SHA1/6 位/30 秒，允许
    ±1 时间步的时钟偏差）；
  - 凭证比较使用**常量时间**比较，避免时序侧信道；
  - **登录暴力破解防护**：按客户端 15 分钟窗口、10 次失败后临时封禁
    （返回 429），状态仅在内存且自动过期；
  - 可选 **Bearer Token** 供脚本使用（同样只在内存/环境变量，不写日志）。
- **机密性**：`config.json`、`totp.json` 以 `0600` 写入；目录 `0750`。
- **日志卫生**：访问日志不记录请求体、查询串或凭证路径；令牌路径脱敏。
- **最小化**：见第 3 节。

---

## 6. 数据主体权利（Art. 15–20）

Skyfire 是运维工具，数据主体通常是**你自己的用户/设备**。软件提供以下能力，
便于控制者响应请求：

| 权利 | 实现方式 |
| --- | --- |
| 访问 / 可携带（Art. 15/20） | `GET /api/interfaces`（含 Peer 详情）返回该接口的全部业务数据；`GET /api/interfaces/{name}/config` 导出服务端配置 |
| 更正（Art. 16） | `PUT /api/interfaces/{name}/peers/{key}` 修改 Peer 信息 |
| 删除（Art. 17） | `DELETE /api/interfaces/{name}/peers/{key}` 删除单个 Peer；`DELETE /api/interfaces/{name}` 删除整个接口及其全部 Peer |
| 限制处理 | 停用接口（`POST /api/interfaces/{name}/up` `{"up":false}`）或禁用 Peer |

> 删除 Peer/接口会同时移除其密钥、令牌、地址与运行状态；不保留副本。

---

## 7. 认证与凭证管理

- **Web 登录**：用户名 + 密码 + 动态验证码；首次登录扫码绑定。
- **TOTP 恢复**：设备丢失时用 `sudo skyfired totp reset` 清除绑定，下次登录
  重新绑定；`sudo skyfired totp status` 查看状态与当前验证码。
- **密码**：为空时每次启动随机生成并打印一次到日志（便于首次使用）；建议用
  `-password` 或 `EnvironmentFile`（`chmod 600`）固定，避免留在日志中。
- **客户端令牌**（`clientToken`）是 `GET /api/p/{token}/wg.conf` 的凭据：请按
  密钥保管，且该端点应仅在 HTTPS 下暴露。

---

## 8. 数据泄露（Art. 33/34）

- 访问日志包含认证结果与状态码，可用于发现异常访问（如大量 401/429）。
- 若发生泄露，控制者应按适用法律在 72 小时内评估并通知监管机构/数据主体。
- 建议启用 HTTPS、关闭 `-demo`/无认证模式、定期轮换 `clientToken` 与 Peer 密钥。

---

## 9. 部署合规清单

- [ ] 控制台置于 HTTPS 反向代理之后，且 `clientToken` 端点不可明文访问。
- [ ] 使用强密码与 TOTP；不要长期使用自动生成的随机密码。
- [ ] 为服务日志配置轮转与保留上限，并在隐私声明中注明保留期。
- [ ] 限制 `config.json`/`totp.json` 的访问（默认 `0600`，属主为运行用户）。
- [ ] 定期审计 Peer 列表，删除不再使用的设备（Art. 5(1)(e)）。
- [ ] 如需处理欧盟数据主体数据，准备 Art. 30 处理活动记录与隐私声明。

---

## 10. 代码层面的合规要点（本次加固）

- 新增 `internal/totp`：RFC 6238 实现，TOTP 密钥以 `0600` 持久化，默认开启、
  首次登录绑定。
- `handleLogin` 改为**常量时间**比较用户名/密码，并校验 TOTP；增加失败计数与
  临时封禁（内存态、15 分钟）。
- 访问日志新增 `redactPath`，令牌化端点（`/api/p/...`）不再写入日志。
- `store.Save` 将 `config.json` 权限由 `0640` 收紧为 `0600`。
- 新增公开端点 `GET /api/auth`，仅暴露“是否需要密码/是否已绑定 TOTP”，用于
  登录页渲染，不泄露任何凭证。
